# Harness 任务卡与验收模板

## 任务卡

```markdown
### 任务：<一句话目标>

用户价值：<完成后谁得到什么改善>

允许修改：
- <文件或目录>

输入与前置条件：
- <输入样例、依赖、已完成任务>

完成标准：
- [ ] <可观察的行为 1>
- [ ] <可观察的行为 2>
- [ ] <边界或错误行为>

验证命令 / 操作：
- `<command>`
- <浏览器或设备操作>

不能做：
- <非目标或需要人工确认的动作>

交付说明：
- 改动文件：
- 验证结果：
- 未验证部分 / 已知风险：
```

## 验收样例的最小集合

为每个核心流程准备：

1. 一个正常输入。
2. 一个空输入或缺失字段输入。
3. 一个冲突、越界或异常格式输入。
4. 一个重复执行或重置场景。
5. 一个用户实际使用环境，例如手机宽度、生产构建或真实文件。

如果任务涉及事实整理，额外检查：事实、推断、待确认项和原文依据没有混在一起。缺少依据时标注缺失，不为了填满模板而创造内容。
