# Harness 交付检查清单

## 上下文

- [ ] README 能说明启动、使用和验证方式。
- [ ] 代码目录职责清楚，任务可以定位到合理文件。
- [ ] 设计、产品目标和非目标已记录。
- [ ] 低频资料没有堵在主流程或单次 Prompt 中。

## 约束与安全

- [ ] 允许修改的范围明确。
- [ ] 外部写入、发布、删除和敏感数据有确认门。
- [ ] 测试使用脱敏或虚构数据，不依赖不必要的密钥。
- [ ] 没有把一次性演示权限扩大成长期权限。

## 验证

- [ ] 核心规则有自动化测试或确定性检查。
- [ ] 正常、缺失、冲突、越界和重复执行都有样例。
- [ ] 浏览器或真实设备验证了关键用户路径。
- [ ] 生产构建或交付命令已运行。
- [ ] 失败信息可以帮助定位下一步，而不是只有“失败”。

## 维护

- [ ] 改动有版本或可比较的差异。
- [ ] 验证结果和未验证部分已记录。
- [ ] 失败后有可恢复路径。
- [ ] 下一个人或 Agent 能继续修改，不依赖原始聊天上下文。
