# AI 学习知识构建器

把“我看过一篇 AI 内容”转化为“我能理解、复述、实践和持续更新的 AI 知识资产”。本 skill 专门服务于 AI 领域学习，不把材料泛化成普通摘要。默认采用“Markdown 知识底稿 + 适合主题的可视化或交互展示”双层结构。

## 适用输入

- AI 基础概念：大模型、Transformer、Embedding、RAG、Agent、多模态、推理、幻觉、评测等
- AI 工程与产品：Prompt、Function Calling、MCP、Workflow、上下文工程、模型选型、部署、成本、延迟与安全
- AI 应用与行业：办公自动化、内容生成、企业 AI、AI 原生产品、垂直场景案例
- 研究资料：论文、技术报告、官方文档、发布说明、实验结果和 benchmark
- 用户自己的学习笔记、提问、实践结果、错误记录和复盘

## 仓库边界

所有产物默认保存到当前仓库：

```text
docs/ai-learning/
├── concepts/       # AI 概念与机制
├── methods/        # Prompt、RAG、Agent、Workflow 等方法
├── tools/          # 工具、模型、API 与产品资料
├── cases/          # 可复用案例与实践拆解
├── research/       # 论文、报告和技术事实核查
├── practice/       # 练习、实验、错误记录和复盘
├── visual/         # 架构图、信息图和知识卡片
├── interactive/    # 可交互 HTML 学习页面
└── slides/         # 授课或分享用演示材料
    
README.md           # 索引与学习路径
```

首次使用时创建缺失目录和索引；沿用已有文件，避免重复创建同主题条目。不要调用 Smart Mind API，不要把内容保存到仓库之外，除非用户指定了其他路径。

### Markdown 保留规则

- Markdown 是知识底稿和长期检索入口，任何新增 HTML、图片、动画或演示都不能替代或删除已有 Markdown。
- 生成其他形式时，必须在展示页中链接回对应 Markdown；Markdown 中也应链接到派生的 HTML、图像或演示文件。
- 更新内容时优先修订 Markdown，再同步派生展示；如果派生展示暂时不同步，明确标记其生成日期和对应底稿版本。
- 除非用户明确要求删除，否则不删除、覆盖或移动已有知识文档；有重大版本差异时新建版本并保留旧文档。

## 输出形态选择

根据学习目标选择最小但足够的输出组合，不为“形式丰富”而堆产物：

| 模式 | 默认目录 | 适合内容 | 主要要求 |
| --- | --- | --- | --- |
| `note` | 原主题目录 | 深度知识、来源、代码、结论 | 必须生成/维护 Markdown 底稿 |
| `visual` | `docs/ai-learning/visual/` | 架构、关系、对比、时间线 | 用图解释关系，不用装饰替代文字 |
| `interactive` | `docs/ai-learning/interactive/` | Agent 循环、RAG、工具调用、参数实验 | 纯静态 HTML 优先，离线可打开，显示输入/过程/输出/指标 |
| `lesson` | `docs/ai-learning/interactive/` | 分步骤教学、测验、主动回忆 | 每页聚焦一个学习目标，提供即时反馈 |
| `slides` | `docs/ai-learning/slides/` | 授课、分享、演讲 | 一页一个观点，链接回知识底稿 |

推荐顺序：先 `note`，再按主题需要选择 `visual`、`interactive` 或 `lesson`。涉及 Agent、Harness、RAG、Workflow、评测或系统架构时，优先增加 `interactive`；涉及概念关系时，优先增加 `visual`；需要授课时再增加 `slides`。

## 交互式 HTML 要求

当使用 `interactive` 或 `lesson` 模式时：

- 文件应能在没有后端和外部服务的情况下打开；如果必须联网或调用 API，明确标注依赖和不可用时的静态替代内容。
- 交互必须服务于一个可观察的学习变量，例如模型、上下文、工具、记忆、验证器、重试次数、成本或延迟。
- 至少包含“概念说明 → 操作/选择 → 结果变化 → 解释 → 复习问题”闭环。
- 对 Agent 类主题，优先展示状态流转、工具调用、环境反馈、验证和回滚，而不是只做按钮动画。
- 不把模拟结果伪装成真实模型评测；使用“示例模拟”或“本地实验”标签，并说明指标定义。
- 共享样式和交互组件应放在当前项目已有约定目录中，避免把大段重复 CSS/JavaScript 内联到每个页面。

## 动画与图文要求

- 动画用于表现时间、循环和状态变化，例如 `决策 → 工具 → 环境反馈 → 验证 → 下一轮`；静态关系使用架构图或表格。
- 图文页必须保留关键术语、输入/输出、流程步骤和边界，不得只生成漂亮但不可学习的海报。
- 每张图或动画旁边提供文字说明和底稿链接，确保无法渲染媒体时仍能完成学习。

## AI 垂直分析框架

先判断材料的主类型，再选择分析重点：

| 类型 | 必须回答的问题 |
| --- | --- |
| 概念/机制 | 它解决什么问题？输入、过程、输出是什么？与相邻概念如何区分？ |
| 方法/流程 | 什么时候使用？步骤是什么？关键参数、失败模式和检查点是什么？ |
| 模型/工具 | 能力边界、适用场景、成本/延迟、数据与权限风险是什么？ |
| 论文/研究 | 问题、方法、实验、基线、指标、结论和局限分别是什么？ |
| 案例/产品 | 用户痛点、AI 介入点、工作流、人工审核和可复用条件是什么？ |
| 学习记录 | 我原来怎么理解？哪里错了？用什么例子验证？下一步练什么？ |

分析时至少建立以下关系：

`问题 → AI 能力 → 技术机制 → 工作流 → 输出 → 验证 → 风险与边界`

对技术内容保留原始术语、API 字段、代码、公式、模型名称和版本。首次出现时给出简短白话解释，例如 `Embedding（把文本映射为可计算向量）`，但不要用通俗比喻替代机制本身。

## 输出文档要求

每篇文档根据材料情况包含以下部分，不必为了凑齐而添加空洞章节：

1. `一句话结论`：读者看完后应记住什么。
2. `这是什么 / 为什么重要`：给出边界和应用背景。
3. `核心机制或论证链`：用步骤、表格、因果链或 Mermaid 图解释。
4. `关键术语表`：英文原词、中文解释、与相邻术语的区别。
5. `实例或最小实践`：保留足够的输入、操作、输出和检查方式。
6. `事实与观点分层`：明确标注来源事实、作者观点、个人推断、待验证信息。
7. `常见误解与失败模式`：说明为什么错、如何识别、如何修正。
8. `可迁移的实践原则`：只提炼能迁移到其他 AI 任务的原则。
9. `复习与行动`：3—5 个主动回忆问题、一个小练习和下一步学习建议。
10. `来源与版本`：原始 URL、作者/机构、发布日期或版本、访问日期和核验状态。

## 事实核验与联网

- 涉及当前模型能力、价格、API、版本、产品功能、政策或 benchmark 时，必须核验官方来源，并记录日期。
- 论文优先使用论文原文、作者页面或官方项目页；产品信息优先使用官方文档和发布说明。
- 如果只有用户提供的材料，标记为“来源材料中的说法”，不要伪装成已独立验证的事实。
- 不把营销语言、单个案例或模型自述直接写成普遍结论。
- 引入外部事实时保留可点击链接；没有可靠来源则写入“待验证”，不要编造引用。

## 文件命名与索引

- 文件名使用小写英文或拼音短名，稳定且可搜索，例如 `rag-chunking-basics.md`、`agent-verification-loop.md`。
- 文档顶部包含 `主题`、`类型`、`难度`、`状态`、`来源` 和 `最后更新` 元数据。
- 更新现有主题时优先编辑原文档，而不是创建同义重复文件。
- 每次新增或重命名文档，都同步更新 `docs/ai-learning/README.md` 的分类索引和推荐学习顺序。
- 对尚未理解或仅有摘录的内容使用 `状态: draft`；经过实践或来源核验后再改为 `reviewed`。

## 质量门槛

保存前检查：

- 读者能用自己的话解释核心概念，而不是只看到摘要。
- 机制、流程、例子和边界没有被混成一句泛化结论。
- 原文观点、事实核验和新增分析有清楚边界。
- 技术术语和关键代码没有因“通俗化”而丢失。
- 至少有一个可执行的实践或验证动作；纯理论材料则提供主动回忆题。
- 文档在当前仓库中可通过 README 找到，相对链接有效。
- 没有将密钥、令牌、私人信息或未授权的受限资料写入 Git。

## 交付说明

完成后报告：新增或更新的仓库文件、所属 AI 主题、是否进行了外部核验、仍待验证的内容，以及建议的下一步练习。不要声称已经提交或推送到 GitHub；除非用户明确要求，否则只修改当前工作树。
