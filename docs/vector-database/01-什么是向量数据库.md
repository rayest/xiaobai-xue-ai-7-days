# 什么是向量数据库

## 1. 从关键词检索到语义检索

传统倒排索引擅长回答“是否包含这个词”。向量检索把文本、图片、音频或用户行为转换成一串数字（向量），再按距离寻找“意思相近”的对象。例如，查询“如何办理退款”可以命中“退货及退款流程”，即使两者没有完全相同的关键词。

一个向量数据库通常保存：

- **向量**：固定或可变维度的浮点数组，来源于 Embedding 模型。
- **ID**：文档、图片、商品或用户行为的唯一标识。
- **Payload/Metadata**：业务字段，如租户、部门、语言、时间、权限、商品类目。
- **索引**：用于快速近似最近邻（ANN）搜索的结构。

它不是关系数据库的替代品。订单、权限主数据和事务状态仍应放在关系数据库或业务系统里；向量数据库负责高效候选召回，并与其他系统协作。

## 2. 基本概念

### Embedding

Embedding 模型把对象映射到向量空间。相近对象在空间中距离更近。模型、语言、维度和训练数据会直接影响检索效果；向量不能跨模型随意比较，换模型通常需要全量重嵌入。

### 相似度

- **余弦相似度**：比较方向，常用于文本语义向量。
- **点积**：对向量内积打分，适合已归一化或模型明确要求点积的场景。
- **欧氏距离**：比较几何距离，适合位置/视觉特征等场景。

必须让距离度量与 Embedding 模型的训练方式一致，并通过离线评测确认，而不是凭感觉选择。

### ANN 与 HNSW

精确搜索要比较查询向量与全部向量，数据量大时成本很高。ANN 通过索引牺牲少量精确率换取更低延迟。HNSW 是常见图索引；`ef_construct`、`m`、查询时的 `ef` 等参数会影响召回率、内存和延迟。

### 稠密、稀疏与混合向量

- **稠密向量**：每个维度通常都有值，擅长语义相似。
- **稀疏向量**：只保存非零维度，擅长关键词、术语和精确匹配，BM25/SPLADE 等方法都可产生类似信号。
- **混合检索**：分别召回，再用加权融合或 Reciprocal Rank Fusion（RRF）合并，通常比单一路径更稳健。
- **多向量**：一个对象包含多个向量，例如 ColBERT 为每个 token 保留向量，再用 MaxSim 聚合，适合更细粒度的语义匹配，但存储和检索成本更高。

## 3. 能够实现什么

- 企业知识库问答、RAG、相似问题推荐
- 商品/内容/职位/课程推荐与相似内容发现
- 图片、音频、视频的以图搜图、跨模态检索
- 语义去重、聚类、异常检测和相似案例检索
- 客服工单路由、相似工单合并、智能搜索
- 个性化检索：向量召回 + 用户/组织/时间等结构化过滤

## 4. 它不能自动解决什么

向量数据库不会自动保证事实正确、权限安全或答案可解释。RAG 仍需要文档解析、切分、元数据、权限过滤、重排、引用、拒答策略和评测；推荐系统还需要反馈闭环与反作弊策略。

## 5. 一次检索的完整链路

```text
原始数据 → 清洗/切分 → Embedding → 写入向量库
用户查询 → 查询改写/Embedding → 过滤 + ANN 召回
          → 稀疏/混合召回 → 重排 → LLM/业务排序 → 返回结果
```

常见故障定位也沿着这条链路：结果为空看过滤和索引；结果不相关看切分、模型和召回；结果相关但答案错误看重排、上下文拼装和生成约束；线上变慢看索引、分片、缓存和并发。
