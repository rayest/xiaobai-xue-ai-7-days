# 企业级架构与落地案例

## 1. 推荐的生产分层

```text
数据源/业务库
  → CDC/批处理 → 文档解析、清洗、切分、脱敏
  → Embedding 服务（模型版本、限流、缓存）
  → 向量数据库（副本、索引、payload、快照）

用户/API 网关 → 鉴权与租户上下文 → 查询改写/Embedding
  → 过滤 + 稠密/稀疏召回 → 重排 → LLM/业务服务 → 引用与审计
```

向量库的主键应能关联原文系统；原文、权限和版本以权威系统为准，向量库保存检索所需的副本和可追溯元数据。

## 2. 案例一：企业知识库 RAG

**目标**：员工询问制度、产品文档和 SOP，返回带引用的答案。

**设计**：按标题层级和语义边界切分；保存 `doc_id`、`section_id`、`tenant_id`、`acl`、`language`、`updated_at`、`embedding_model`、`content_hash`；使用稠密 + BM25/稀疏混合召回，Top-50 后重排 Top-8；生成答案强制引用片段，没有证据就拒答。

**关键指标**：Recall@20、MRR、引用准确率、无依据回答率、P95 延迟、单次问答成本、权限越权率。

**上线要点**：文档更新通过 outbox/队列驱动幂等索引；新旧模型双写到不同 namespace；权限变更要有快速失效机制，不能等待异步重嵌入。

## 3. 案例二：客服工单相似检索与路由

**目标**：新工单自动找到相似历史处理方案并推荐队列。

**设计**：把标题、现象、日志摘要分开建模；时间、产品版本、地区、客户等级作为过滤或加权特征；相似工单仅作候选，最终由规则/分类器确认，避免把旧的错误答案传播给新客户。

**关键指标**：Top-5 命中率、人工采纳率、平均处理时长、重复工单率、错误路由率和新版本冷启动效果。

## 4. 案例三：多租户 SaaS 知识检索

**目标**：同一集群服务多个客户，同时保证数据隔离。

**设计选择**：小租户共享集合 + 强制 tenant filter；大租户或合规客户独立 collection/namespace/集群。租户上下文由网关从令牌解析，应用层禁止客户端覆盖。建立 tenant 维度索引，记录每次查询的租户、用户、过滤摘要和结果文档 ID。

**隔离验证**：构造跨租户相同关键词、相同向量、删除后查询、缓存命中和异常重试场景，自动化验证结果集合永不越界。

## 5. 案例四：商品与内容推荐

**目标**：根据用户行为召回相似商品/内容。

**设计**：向量召回只是多路候选之一，还要合并热门、实时库存、规则、探索和去重；过滤价格、地域、库存和合规；线上反馈用于重训或调整排序，不能把点击直接当作满意度。

**关键指标**：Recall、CTR/CVR、GMV 或观看时长、覆盖率、多样性、新颖性、延迟、库存命中率和公平性。

## 6. 可靠性与运维

- **高可用**：副本、跨节点分片、故障转移、连接池、限流和降级到关键词搜索。
- **备份恢复**：定期快照 + 异地副本；演练 RPO/RTO，而不是只检查“备份成功”。
- **发布回滚**：schema、Embedding 模型、索引参数和代码都要版本化；支持双写、灰度、重建和回滚。
- **数据治理**：删除请求、保留期限、脱敏、加密、审计和数据驻留策略进入流水线。
- **可观测性**：记录召回数量、过滤命中率、重排耗时、向量模型版本、空结果率、引用率、P95/P99 和成本。

## 7. 企业级最小可行方案

先用一个领域、一个租户和有限文档做端到端闭环：数据同步、Embedding、混合检索、权限过滤、引用、评测、监控、快照恢复。只有当质量和恢复演练通过后，再扩展租户、地域、模型和流量。这样可以把“向量库能否工作”与“企业系统能否负责”分开验证。
