Harness 为什么可能比模型更重要

模型提供潜在推理能力；Harness 决定这些能力能否被组织成长期、可执行、可验证的任务结果。

先别急着换模型先检查上下文、工具、记忆、循环、验证器和权限，看看问题是否其实发生在模型外面。
本页是示例模拟，不是真实模型评测。 指标用于理解“系统配置如何改变结果”，底层知识与来源请阅读 Markdown 知识底稿。

一个 Agent 到底由什么组成？

裸 LLM 是“tokens in → tokens out”的序列处理器。Harness 把它放入一个能观察环境、调用工具、管理上下文并反复验证的闭环。

实际任务能力 ≈ 模型能力 × Harness 有效利用率 × 环境可执行性 × 验证可靠性
目标用户想完成什么
→
上下文编译决定模型看见什么
→
模型决策输出下一步动作
→
工具 / 环境执行并反馈
→
验证 / 记忆修正并积累

边界要记住

Tool 通常是 API；Skill 更像可复用的任务程序；Memory 保存跨任务状态；它们都不等于模型权重学习。

三条工程判断

  1. 先测系统，再换模型：固定模型，逐步加入上下文编译、工具和验证器，确认增益来自哪里。
  2. 反思不等于验证：模型说“我检查过了”只是另一轮生成；验证应尽量连接外部测试、环境奖励或人工批准。
  3. 自我修改必须有门：Agent 可以提出改动，但系统应决定是否接受；代码、数据写入和权限变化尤其如此。
