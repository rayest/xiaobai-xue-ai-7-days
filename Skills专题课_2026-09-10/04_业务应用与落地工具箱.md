# 业务应用与落地工具箱

以下均为场景设计，不是客户案例、实测收益或服务承诺。先选一个可以试验的场景，不必一次建立全公司的 Skill 库。

## 1. 十六个业务场景

| 场景 | 输入 → 产出 | 值得固化的规则 | 人工验收点 |
| --- | --- | --- | --- |
| 会议跟进 | 记录 → 决策与行动项 | 承诺与建议分开，缺人缺日期标记 | 原文依据、责任归属 |
| 运营周报 | 指标与事件 → 周报 | 先定义口径，再比较；区分事实与解释 | 分母、周期、重复数据 |
| 品牌内容 | 产品事实 → 文案初稿 | 语气、禁用承诺、品牌词表 | 数字、口径、发布前审批 |
| 短视频策划 | 选题与事实 → 分镜稿 | 开场、演示步骤、镜头所需素材 | 可拍性、事实与素材权利 |
| 课程教案 | 学员与时长 → 流程 | 按成果倒推、分层、时间合计 | 实操可行性、时间负荷 |
| 练习题编写 | 教材 → 题目与答案 | 题目对应目标，答案可从材料获得 | 歧义、难度、知识错误 |
| 销售拜访准备 | 客户资料 → 沟通提纲 | 已知事实、假设、待问问题分开 | 客户信息新鲜度、来源 |
| 客户跟进草稿 | 沟通记录 → 邮件草稿 | 不擅自承诺报价和交期 | 商业承诺、收件人 |
| 客服知识整理 | 已批准答复 → FAQ | 合并同义问题，保留适用条件 | 政策版本、升级转人工条件 |
| 售后分类 | 工单 → 分类与建议 | 用既定类别，证据不足不直接定责 | 分类准确、个人信息 |
| 招聘材料整理 | 简历与岗位要求 → 对照表 | 只列与工作相关的证据与缺项 | 避免无依据推断，不自动最终录用 |
| 新人入职 | 岗位资料 → 检查清单 | 必修顺序、资源入口、负责人 | 链接可用、制度有效 |
| 项目复盘 | 过程与结果 → 复盘草稿 | 事实、解释、可验证改进分开 | 不凭结果倒推单一原因 |
| 合同信息摘录 | 合同 → 条款对照 | 保留原文、页码、待专业确认点 | 仅辅助摘录，专业人员判定 |
| 报销初审材料 | 票据 → 缺项表 | 按提供制度检查字段和重复 | 不替代付款批准 |
| 网页验收 | 页面与需求 → 问题单 | 按用户路径检查，保留复现证据 | 真正复现、浏览器环境 |

有些场景需要文件解析、数据库或浏览器工具。上述场景名称是可以自行设计的业务 Skill，不代表存在同名官方安装包。

## 2. 选第一个场景：五项打分

每项 0–2 分：频率（偶发/每月/每周以上）；规则稳定（变化大/部分稳定/稳定）；输入可得（困难/要整理/现成）；结果可验（难/部分/清楚）；错误可纠（代价高/可控/易修正）。满分 10 分。

课堂建议：8–10 分优先试点，5–7 分先补规则或数据，0–4 分换题。阈值是教学用启发，不是经过验证的行业标准。涉及重大决定、付款或外发的部分应拆成草稿与实际动作，分别设置真实权限和审核责任。

例：会议行动清单可给 2+2+2+2+2=10 分，适合本课；自动谈判并签客户合同即使频率高，也不适合作为第一节课的放手执行任务。

## 3. 三个完整设计案例

### 案例 A：培训机构的教研工作

痛点：教案有知识列表，却没有学员产出；不同老师无法按同一课时完成。

输入合同：学员基础、授课时长、已确认工具、可用素材、课程目标。方法：按成果倒推流程，为每段添加学员动作，给低基础学员备用方案。输出合同：分钟表、材料清单、练习题、验收方式。模板见本包 course-outline。

试点：一门熟悉课程、两位老师、三种课时版本。测量实际超时、练习完成率和老师修改时间。失败例：“把 60 分钟排成 75 分钟”；修订：把休息、演示等待和答疑都纳入总时长。不要把“满意度提升”提前写成实际结果。

### 案例 B：小团队的品牌内容

痛点：每次文案都要删夸大词，AI 不清楚产品能承诺什么。

输入合同：产品事实、目标受众、渠道、CTA。方法：场景开头、产品事实核验、口吻约束。输出合同：标题、正文、事实清单。品牌规范放 references，具体活动日期留在任务输入中。

试点：10 篇初稿，小组盲评，记录未被资料支持的数字数量、修改耗时、品牌表达一致性。不要把内容上线后的转化变化直接归因于 Skill；渠道流量、活动和人群也会改变结果。

### 案例 C：客户成功的跟进准备

痛点：沟通历史散落，跟进草稿遗漏未解决问题。

输入合同：脱敏沟通记录、产品支持边界、已有承诺。方法：先整理承诺，再列未解决问题，最后起草下一步。输出合同：事实表、待问问题、邮件草稿。若接 CRM，再由已授权工具取数，Skill 描述字段与口径。

试点：先用导出材料离线验证；确认引用和承诺无误后，再讨论实时连接和发送。发送环节不得仅因为 Skill 中写着“发送”就视为获授权。

## 5. 效果怎么计算

每件净节省时间 = 原人工处理时间 − 使用后的输入准备、等待、审核、返工和分摊维护时间。

月度时间收益 = 每件净节省时间 × 实际处理件数。若希望换算成本，再结合团队自己的小时成本，扣除工具与维护费用。可节省的时间不必然等于可兑现的现金。

假设示例：原 30 分钟；使用后准备 3 分钟、等待 2 分钟、审核 8 分钟、返工 2 分钟、分摊维护 1 分钟，合计 16 分钟；每件节省 14 分钟。每月 20 件则节省 280 分钟，约 4.7 小时。全部是演算假设，不是课程效果数据。

同时记录质量：事实错误数、遗漏率、一次验收通过率、需人工接管次数。省时但关键错误增加，不应判定成功。

## 6. 小团队两周试点

| 阶段 | 工作 | 产出 |
| --- | --- | --- |
| 第 1–2 天 | 选场景，整理脱敏样本与人工基线 | 需求卡、输入输出 |
| 第 3–4 天 | 写最小 Skill，处理已知失败 | 初版与测试表 |
| 第 5 天 | 同事独立使用 | 可理解性和失败记录 |
| 第 6–8 天 | 在小范围真实工作里使用 | 耗时与质量记录 |
| 第 9 天 | 检查例外与维护成本 | 修订与回归结果 |
| 第 10 天 | 决定继续、缩小或停止 | 一页结论 |

## 7. 团队维护的最小账本

记录名称、负责人、适用范围、资料版本、依赖、验证过的客户端、测试日期、已知限制和回退版本。上线新版本前先保留旧版本及失败样本。规则、模型或工具变化后，选关键案例重新测。

同一个通用 Skill 不要堆入所有部门的冲突规则。公共方法保持小，各部门口径放专用参考资料或独立 Skill。先保证职责明确，再考虑插件打包和集中分发。
