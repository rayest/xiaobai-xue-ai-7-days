# 自定义 Skill 工作纸

这是供人填写的模板，不是可直接安装的完整 Skill。填完业务内容后，请 Codex 创建实际目录，再做结构与行为检查。

## 先用自然语言说清楚

```text
请把下面这项重复工作做成一个小型 Agent Skill。
名称：填写简单的小写英文名称，用连字符分词。
使用情境：谁在什么情况下用。
不适用情境：最可能混淆的任务。
输入：我能提供哪些资料。
输出：交付什么文件或内容。
关键规则：写出最影响结果的 3–5 条。
缺项与冲突：如何处理不知道和相互矛盾的信息。
参考资料：哪些规则每次用，哪些只在特定情况用。
测试：提供正常、缺失、冲突、不相关四种测试请求。
请先做纯文本版本，保存到我指定的练习项目目录。
不要替我编造业务规则；缺少关键内容时先指出缺口。
```

## 文件形状参考

将以下示意中的方括号替换为真实内容。不要把此工作纸原样当作技能入口。

```markdown
---
name: my-business-task
description: [具体做什么；什么情况下使用；必要的边界。]
---

# [业务任务]

## 输入与目标

[必需输入、缺失时如何处理、期望结果。]

## 判断与处理

[真正影响结果的规则；有多种合理方案时给判断依据。]

## 交付与检查

[格式、保存方式、事实核验、完成标准。]
```

## 写完后给 Codex 的检查请求

```text
请检查这个 Skill 的名称、描述与目录是否一致，引用文件是否存在，
是否混入了本次任务的私人信息或不应长期保存的事实。
再指出最可能误触发的请求、最可能做错的边界，以及一项最小修改建议。
结构检查与实际模型测试请分开报告；没有运行的测试不要声称已通过。
```
