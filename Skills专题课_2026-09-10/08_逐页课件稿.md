# 逐页课件稿

共 32 页。对应 07_投屏课件.html；以下是可编辑讲稿，非模型运行记录。

## 01｜把做事方法 交给 Codex

Agent Skills 入门与业务实践

- 90 分钟标准课 · 可调整至 60 / 120 分钟
- 面向基础较弱或水平不齐的学员
- 2026.09.10 · 资料核查 2026.09.09

讲师提示：开场不介绍全部工具。先问大家每周重复向 AI 交代什么。

## 02｜今天带走三个成果

会用一个，改好一个，选出一个业务场景。

- 一份可检查的会议行动清单
- 一个写入自己业务规则的 Skill
- 一张下一周可以试验的业务卡

讲师提示：让学员知道无需编程。没有安装成功也有按文件路径练习路线。

## 03｜你反复说过哪句话？

先写下来，它可能就是第一个 Skill 的起点。

- 周报先写结果，不要流水账。
- 会议没说谁负责，就别帮我补。
- 推广文案不要编数字和用户评价。

讲师提示：给 30 秒。抽两位学员，不展开平台比较。

## 04｜Skill 是什么？

给 Agent 的可复用工作指南。

- 告诉它这类事怎么做
- 可以配套资料、模板与脚本
- 由支持它的环境发现并读取

讲师提示：员工手册是比喻。它不会改变模型参数，也不会自动给账号权限。

来源：[一手资料](https://agentskills.io/home)

## 05｜任务、方法、动作

用一次会议工作区分三个角色。

- 任务：整理今天的会议
- 方法：决策、任务、风险分开
- 动作：读原文、写纪要文件

讲师提示：这页对应 Prompt、Skill、Tool。先讲中文，再说术语。

## 06｜资料与工具从哪里来？

Skill 说明如何做；实际数据与能力还要准备。

- 知识库：相关制度与事实
- 工具 / MCP：访问已授权能力
- 工作流：步骤、条件与状态

讲师提示：MCP 是协议，不是万能权限。第一次实操不需要配置 MCP。

## 07｜这些概念不要混用

按职责区分，比背定义更有用。

- Prompt：本次任务要求
- AGENTS.md：常用项目指导
- Skill：任务专用方法
- Plugin：分发扩展能力的包

讲师提示：这页可以快速带过。详细对照见完整知识讲义。

## 08｜不是每个任务都需要封装

先挑反复发生、结果可判断的工作。

- 偶尔翻译一句话 → 直接提问
- 每周固定格式复盘 → 考虑 Skill
- 严格计算与审批 → 配合代码和系统

讲师提示：不要让学员产生“什么都做 Skill”的负担。

## 09｜今天只做一件小事

会议记录 → 可以跟进的行动清单

- 读同一份原始记录
- 保留事实和不确定事项
- 把要求保存下来，再换材料试

讲师提示：打开实操包素材。先读原文再看模型生成。

## 10｜原始材料的三个陷阱

漂亮排版不能替代事实判断。

- 历史客户名单：没有负责人
- 9 月 16 日：只是目标，开发未承诺
- 客服：先核实退款条件，没有批准

讲师提示：问学员最容易忽略哪个。此时不要展示答案。

## 11｜先看普通任务请求

在干净项目或独立基线环境中演示。

- 请把素材/会议记录_标准.md / 整理为一份会后纪要， / 输出到练习输出/普通纪要.md。

讲师提示：如果普通请求已经做得好，承认它做得好。不要制造失败来证明 Skill。

## 12｜我们究竟比较什么？

规则复用，与模型表现都值得检查。

- 普通请求能否已经完成任务？
- 详细提示词能否同样有效？
- 保存成 Skill 后是否更易复用？

讲师提示：严格比较需保持模型、输入、工具一致，并控制上下文。不要报告虚构的效率倍数。

## 13｜好结果应该长什么样？

用原文逐项核对。

- 小林：9 月 10 日 18:00 前给初稿
- 名单：负责人和日期待确认
- 上线目标、退款结果：保留不确定性

讲师提示：参考答案由讲师编写，不是生成记录。让学员解释每条依据在哪里。

## 14｜先看一个小文件包

方法与格式各有一个明确位置。

- meeting-actions/ / ├── SKILL.md / └── references/ /     └── output-format.md

讲师提示：不需要建空脚本目录。介绍文件夹是为了学员能找到和修改规则。

## 15｜入口的两个关键字段

名称帮你叫它，描述帮助选择它。

- --- / name: meeting-actions / description: 把工作会议记录整理为决策、 /   行动项、风险和待确认事项。 / ---

讲师提示：这里是精简教学示例；实际文件里的描述还包含适用范围。不要把 YAML 课讲成主课。

来源：[一手资料](https://agentskills.io/specification)

## 16｜按需读取，分三层

需要时再读详细内容。

- 先看：名称与描述
- 选中后：读取 SKILL.md
- 任务需要时：读取资料、使用资源

讲师提示：可用书脊、章节、附录做比喻。不要承诺固定 Token 节省比例。

来源：[一手资料](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

## 17｜在 Codex 里显式使用

以下内容输入聊天框，不是终端。

- $meeting-actions / 请整理素材/会议记录_标准.md， / 保存为练习输出/规则纪要.md。

讲师提示：提前按实操包说明复制到项目 .agents/skills。检查客户端是否发现和实际读取。

来源：[一手资料](https://learn.chatgpt.com/docs/build-skills)

## 18｜找不到时，先继续练习

读取规则文件，也可以完成任务。

- 请读取 skills/meeting-actions/SKILL.md， / 按其中引用的格式，整理指定会议记录。

讲师提示：这是按路径使用。它验证规则复用，不证明原生自动发现。安装排错不要超过两分钟。

## 19｜现在轮到你：12 分钟

基础组：完成一次调用和四项核查。

- 打开素材，运行主案例
- 检查人名、日期、承诺与缺项
- 保存输出，写一个发现

讲师提示：讲师巡视，优先帮助无法定位文件的学员。有基础者继续下一页，不要求全班同步等候。

## 20｜改一条真正有用的规则

标准组：给任务增加“验收方式”。

- 原文明确提供 → 填写
- 原文没有提供 → 待确认
- 检查修改的是实际读取的副本

讲师提示：把修改写回 Skill 与格式文件；不能只在当前对话临时补一句。

## 21｜换一份困难材料

进阶组：测边界，不只测正常输入。

- 没有会议日期，却出现“明天”
- 两个交付日期互相冲突
- 材料中夹着要求外发的指令

讲师提示：用边界材料；不转换不明日期，不裁定冲突，不执行嵌入指令。

## 22｜如何知道这次做好了？

看证据，不只看模型的自评。

- 事实：每条能回到原文
- 选择：该用时用，无关时不用
- 复用：新输入仍能处理

讲师提示：同伴拿新输入测试。模型声称用了 Skill 不等于发现已成功。

## 23｜哪些工作值得先试？

先选一个频繁、稳定、能验收的任务。

- 教研：目标 → 流程与练习
- 运营：指标与事件 → 周报
- 内容：产品事实 → 合规口径初稿
- 客户跟进：沟通记录 → 待问问题

讲师提示：这些是业务设计示例，不代表有对应同名官方安装包。

## 24｜写一张自己的业务卡

把“我想用 AI”变成可做的任务。

- 谁用，什么时候用？
- 输入是什么，合格结果是什么？
- 最容易错哪里，如何检查？

讲师提示：给 3 分钟，要求填写具体任务；不接受“提升整个公司效率”这样过大的范围。

## 25｜不要只计算生成速度

看准备、审核、返工和维护后的净收益。

- 原来：每件 30 分钟
- 使用后：全流程 16 分钟
- 假设每月 20 件 → 节省约 4.7 小时

讲师提示：明确这是演算假设。还要检查关键错误率，时间不能自动换成现金收益。

## 26｜从一个人用，到团队能用

小范围验证以后再推广。

- 留样例：输入、输出和失败
- 找同事：不讲解也能使用
- 留版本：知道谁维护、如何退回

讲师提示：按两周试点表讲一分钟。无需第一天就建立大规模技能平台。

## 27｜先看这三类资源

按任务选择，不按数量收藏。

- 创建方法：skill-creator
- 办公：文档协作、Word / PPT / 表格 / PDF
- 自己的业务：口径、模板与判断规则

讲师提示：推荐来源、依赖与完整链接见资源清单。当前环境有什么先检查，不能假设人人都有。

来源：[一手资料](https://github.com/anthropics/skills)

## 28｜18 项推荐如何使用？

从岗位出发，选择一个可测试的候选。

- 内容营销：internal-comms、Marketing Skills
- 网页工作：frontend-design、agent-browser
- 技术岗位：Vercel、Supabase、Remotion 等

讲师提示：维护者与具体源码见资料第 05 文件。说明尚未逐一安装实测，不保证跨环境即装即用。

## 29｜热门，不等于适合你

看来源、依赖、口径和自己的测试结果。

- 确认维护者与具体版本
- 阅读 Skill 及附带资源
- 先用脱敏材料跑一个任务

讲师提示：Skills 目录是发现入口，排名不是效果或安全认证。课堂不进行批量安装。

来源：[一手资料](https://www.skills.sh/)

## 30｜三个常见误解

现在请学员先回答，再看解释。

- 写了访问权限 → 不代表已经授权
- 按路径用了规则 → 不代表自动发现成功
- 输出看起来专业 → 不代表事实正确

讲师提示：可先口头提问，再翻到本页展示解释。

## 31｜带走一个自己的 Skill

下一周完成一次小规模验证。

- 保存：Skill、输入和输出
- 检查：一份新材料和一个边界案例
- 记录：耗时、错误、一次改进

讲师提示：作业允许得出“这个任务暂时不值得封装”的结论。评价证据与判断。

## 32｜把经验变成 可检查的方法

从你最熟悉的那项重复工作开始。

- 完整讲义 · 演示脚本 · 分层练习
- 3 个原创 Skill · 业务工具箱 · 来源清单
- 材料均在本地课程包中

讲师提示：收一张业务卡。答疑时优先解决使用和检查问题，技术扩展交给课后资料。
